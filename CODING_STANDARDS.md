# Coding standards

Rules that need judgement at review time — cross-file consistency, shape,
boundaries. Mechanical patterns (types, import shape) are left to tooling:
`bun run check` (typecheck + tests). Prefer adding a check to adding a rule here.

Source is formatted by hand: single quotes, and lines may run past 80 columns.
No formatter runs here (`opencode.json` disables formatting), so a whole-file
reformat in a diff is a mistake, not a preference.

The built bundles `status/main.js` and `service/main.js` are generated by
`bun run build` and committed so OpenChamber can install the extension from the
repository URL. Never edit them by hand; regenerate and commit them instead.

## Architecture

- **The service is behind a seam.** `service/app.ts` exports
  `createService(deps)`; `service/main.ts` only reads the host-issued port and
  bearer and binds loopback. Tests drive real HTTP through `createService` with an
  injected `fetch`, `readText`, clock and environment — never the process
  bootstrap.
- **The service never hands the guest an internal error.** The unhandled-error
  catch logs locally and returns a generic `upstream_error`; a message that crosses
  the wire is one the code chose to write.
- **Pure logic is separated from I/O.** `status/view-model.ts` builds the strings
  the section shows and touches no DOM; `service/dates.ts` is the calendar maths,
  taking the instant or the zone it needs. The surface modules are `status/app.ts`
  (wiring + DOM) and the bundle entries `status/main.ts` and `service/main.ts`.
- **One wire contract.** The JSON shapes that cross `serviceRequest` live in
  `shared/wire.ts` as types only; both sides import them with `import type`. Raw
  LiteLLM JSON never crosses the wire — normalise it in `service/litellm.ts`.
- **The service is read-only and local.** It binds loopback, requires the
  host-issued bearer on every route (including `/health`), and makes no LiteLLM
  writes.

## Tests

- **Assert external behaviour, not structure.** Drive the pure modules with table
  cases; drive the section through a stub host and assert on the rendered DOM;
  drive the service over real HTTP against a fake LiteLLM. Do not reach into
  private state.
- **Distinguish failure from absence.** A failed read is an error; an empty result
  is a different state (`config_read_error` vs `no_provider`). Both are labelled
  apart, never conflated.
- **Inject the clock and the zone.** Anything that depends on "now" or a timezone
  takes it as a parameter, so it is testable across local midnight and a DST
  boundary.

## Language

- **Use `GLOSSARY.md` terms**, and avoid their `_Avoid_` synonyms (e.g. say
  _Budget window_, not _limit_; _Quota used_, not _usage_; _Spend_, not
  _cost_).
- **The extension is "LiteLLM Usage"** — that exact name is the section title and
  the panel document title.
